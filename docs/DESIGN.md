# Playscript 设计存档

从**分镜视频帧**提取台本（镜号 / 角色 / 台词）的工具。

> 注：项目文件夹计划改名为首字母大写 `Playscript`。因当前会话工作目录占用该文件夹，
> Windows 不允许重命名「正在被进程用作当前目录」的文件夹，需**关闭会话后**在资源管理器/终端
> 里改名（Windows 大小写不敏感，改名后路径照常工作，零影响）。

## 背景与约束
- 分镜视频字幕由分镜师用别的软件（TBS 等）制作，**拿不到源工程，只有成片**。
- 字幕**烧录进画面像素**；OCR 是主路径（STT 放弃：分镜片多为草轨/无声，画面已含全部文字）。
- 镜号由使用者**重新排序**，且不重新导出视频 → 需要人工在 PR 时间线上逐帧定位抓取。
  因此最终形态是 **PR 扩展面板**（CEP），而非独立批处理工具。

## 帧画面布局（实测 1920x1080）
| 区域 | 位置 | 内容 | 用途 |
|------|------|------|------|
| 底部中间 | y≈946，居中 | `说话人：台词`（冒号前可含 `&` 表多人） | ✅ 角色 + 台词 |
| 左上 | y≈68 | `ep01_SC002`（使用者重排过的正确镜号） | ✅ 镜号 |
| 右上 | y≈113 / y≈72 | `Sc_002`（分镜师原编号）+ 计数/时间码 | ❌ 丢弃 |
| 顶部 | y≈4 | `说明：…` 场景注释 | ❌ 丢弃 |

**位置不写死**：镜号靠 `SC\d+` 正则 + 左上方位；台词靠「中下部 + 含冒号 + 非『说明』」。容忍上下漂移。

## 解析规则
- **镜号**：左上 `ep01_SCxxx` → 取 SC 后数字（保留前导零，允许 `015a` 这种尾字母）。仅在 SC 上下文把 `一` 当分隔符，绝不全局替换（台词里「一」是常用字）。
  - 候选范围：**左半 + 上部**（`x<50%W && y<45%H`）。
  - 取哪个候选：**先比 y（越小越优先）→ 再比 x → 最后才比「有没有 ep 前缀」**。
    - y 是最稳的判据：重排后的标签贴画面最上沿（实测 y≈25/3240），分镜师原编号在它下面（y≈482）。
    - **不能把 ep 前缀放第一位**：OCR 会把标签的 `e` 认成 `℃`（实测 `a` → `℃ p 27`），前缀判据当场失效；而原编号 `MX-EP001-SC048-4` 若被读成整行，它**带着** EP，反而会抢过真标签，静默给出错误镜号。
- **角色 / 台词**：`extractDialogue()`，三步：
  1. **按 y 聚成文字行**（容差 3%H）：同一视觉行常被 OCR 拆成多个框（`小胖孑：` + `我在门口等。`，或 `小北：问题` + `大爷`）→ 必须按 x 拼接，否则丢台词。
  2. **选锚点行 = 最低的含冒号行**（= 台词起点）；整段都没有冒号则取最低行（续行帧，整段当台词、说话人待继承）。
  3. **从锚点向上下扩折行续句**：间隔在 8%H 内且**自己不含冒号**的行并入；含冒号的行不并入（那是另一句台词）。
  - ⚠ 不要再按「这一行有没有冒号」过滤：无冒号的续行（`大爷`）会被整行丢掉——v1.1.1 面板就是这个 bug。
  - ⚠ 也不要「只取最低的那一个 y 带」：折行台词超过 4%H 时间距会把上半句丢掉。
- **帧排序**：按 `(集, 镜号, 子序)`，基名(无后缀)子序记 0，排在 `-2/-3` 之前，保证同镜号时间顺序正确
  （文件名直接排序会因 `-`<`.` 把 `sc059` 排到 `sc059-2` 之后）。
- **说话人继承**：续行(无说话人)从**同镜号的上一帧**继承角色（带告警）。
- **合并**：相邻行**同镜号且同角色** → 台词拼接不换行；中间换了别人说 → 另起一行
  （因相邻上一条即那个别人，条件自然不满足）。
- **多说话人拆分**：角色含 `&` → 每人一行、台词复制（合并之后再拆）。

## 两段式取图（精度几乎全在这一步）

整帧 OCR 是最省事的做法，但两个关键元素都太小：镜号标签在 1080p 上只有二十来像素高，
台词条只占画面底部。整帧放大又受 **OCR 输入长边上限（实测约 10000px）** 卡死。
所以裁开分别放大（`src/ocr/regions.js`）：

| 区域 | 裁切 | 预处理 | 用途 | 实测 |
|------|------|--------|------|------|
| 左上 | 宽 12% × 高 6% | 6x lanczos | 镜号 | 5/6 帧稳定读出 `SC001`（整帧只有 2/6） |
| 底部 | 高 25% | 灰度 + 对比度 1.5 → **bicubic 4x** | 台词 | 字符准确率 **90.6%**（原来白字抠色 84.2%） |
| 整帧 | — | 3x | 兜底 | 老片标签宽 14%（`a_sc050`），只有整帧读得到 |

要点：
- **镜号必须两路合并**：12% 裁切能读到 乙片 的小标签，但会把 甲片 的宽标签切掉；
  整帧那一路正好相反。`extractShot()` 接受多个 OCR 源，统一还原成帧比例后排序。
- 顶着图边（右缘 ≥98%）的候选直接丢弃——那是被裁断的半截编号，宁缺勿错。
- 整帧 OCR 是最贵的一步（~650ms），只在上面两路都读不到时才懒加载。
- 插值选 bicubic 不选 lanczos：实测平均 90.6% vs 89.6%，`小白AI:` 这类中英混排还能读对。
- 台词默认走**灰度**而不是「抠掉白字再取 alpha」：准确率更高，且不假设字幕一定是白色
  （彩色字幕会让抠色整块失效）。面板的字色输入留空即灰度，填了才切抠色。

## OCR 准确率三层防线
1. **放大后识别**：见上表。WinRT `BitmapTransform` 放大（整帧兜底默认 **3x**，插值 **Cubic**），
   显著减少「左右结构字被拆成偏旁」的错误；区域图由 ffmpeg 放大。
2. **纠错表 + 输出规整**（`src/parse/ocrfix.js`）：
   - 偏旁拆分（破坏**内容**，必须精确替换）：`亻壬→任`、`夕卜→外`、`川页→顺` 等，可随用随补。
   - **输出规整（台本一定有人工校对，所以「宁可整齐，不要花」）**：
     - **角色**只允许中文/英文/数字（+ 多说话人分隔符 `&`），标点一律去掉：`小白A《`→`小白A`。
     - **台词**只保留 `，。？！…` 和**书名号 `《》`**：半角转全角、`、；：~·` 等收敛成逗号、
       白名单外的符号（引号、括号、其它书名类符号）直接丢弃、连续标点合并、去掉首尾逗号。
       书名号是正文内容（`《新闻联播》`），必须原样留着；只有角色里的书名号会被去掉。
     - 省略号：连续点号/中点合并；**配不上对的引号**当作被认坏的省略号换成 `……`（成对引号保留）；
       单个 `…` 补成 `……`。
   - **冒号识别**：半角冒号常被认成 `.` `．` `·` 甚至直接吞掉（`小白AI:`→`小白A上`）。
     点号只在前面「像角色名」（≤8 字纯中英文数字）时才当冒号。
   - **角色补全**（`pipeline.repairRoles`）：说话人不含标点这条业务约定可以反过来用——
     拿同片别的帧已经认准的角色名，到「没拆出角色」的行首做**等长近似匹配**（差 ≤1 字），
     把被吞掉的分隔符切掉。实测 `小白A上已抓取片单…` 靠同片的 `小白AI` 还原成
     「小白AI ｜ 已抓取片单…」，并留告警说明这行是补出来的。
3. **人工复核**：低置信/异常行在面板里标 ⚠ 并写进 `title`，在 PR 里边播边改。
   宁可告警也不静默丢字——`镜号未识别`、`无冒号，按续行处理`、`同帧另有 N 行台词未取`、
   `角色按同片已知角色名补全`。

> 实测 乙片 五帧（`pic/1027`）：镜号 **5/5**、角色 **5/5**、
> **内容字准确率 100%**（汉字/英文/数字全对）、含标点 96.2%（差异全是标点收敛）。
> 耗时约 950ms/帧（三帧都不用整帧兜底）；甲片 那种宽标签要跑整帧，约 1.6s/帧。

## 目录结构
```
src/                      ← 唯一真源，面板那份是它的生成物
  ocr/win_ocr.ps1   Windows.Media.Ocr，输出行文本+坐标(JSON)，支持 -Scale
  ocr/ocr.js        引擎封装（win 本地默认 + cloud 预留），默认 scale=3
  ocr/regions.js    两段式取图：左上取镜号 / 底部取台词（ffmpeg 裁切+放大，临时图用完即删）
  parse/parse.js    OCR 行 → 镜号/角色/台词（导出 extractShot / extractDialogue）
  parse/ocrfix.js   偏旁纠错表 + 标点归一化
  merge/merge.js    相邻同镜号同角色合并 + 多说话人展开
  pipeline.js       analyzeFrame（单帧→一条记录）+ buildRows（继承→合并→拆分）
  docx/docx.js      三列表格 docx（对齐 example，可选）
  output/text.js    纯文本输出（默认）：镜号<空格>角色<空格>台词 + 换行
  cli.js            帧目录 → 识别 → 解析 → 合并 → 输出 + 验证报告
scripts/
  sync-panel-src.js 把 src/ 同步进 cep/com.ezplayscript.panel/src/（--check 只检查漂移）
test/
  *.test.js         node --test，含真实帧 OCR 夹具（fixtures/）做回归
cep/com.ezplayscript.panel/
  src/              ⚠ 生成物，勿手改；改根 src/ 后跑 npm run sync
```

## 输出格式
- **默认纯文本**（不生成表格）：`镜号  角色  台词`，两空格分隔，逐行换行。
- 按 `-o` 扩展名选择：`.txt` → 文本；`.docx` → 三列表格（保留）。

## 面板可勾选项（M3 接入 PR 面板的 toggle）
这些当前是 CLI 参数，M3 做成面板复选框，随时可勾：
- 镜号续行：**每行重复** ↔ **留空对齐**（`--merge-shot`）
- 多说话人拆分：`小胖&老周` → 每人一行、台词复制（`--no-split-speakers` 关闭，默认开）
- 列分隔符（`--sep`，默认两空格）
- 放大倍数 / 插值（`--scale`）
- 合并连接符（`--joiner`，默认直接相连）
- OCR 引擎（本地 / 云端，`--engine`）
- 输出格式（txt / docx）

## PR 抓帧（M3 技术要点）
- **现役方案**：Ctrl+Shift+E 原生「导出帧」→ 存到 `~/Desktop/.ezCapture` → 面板轮询 600ms 发现新图 → 识别 → 删源图。
- 面板为省 OCR 成本跑**两遍**：整帧（灰度+对比度）只取镜号；底部 25% 裁切 + 4x Lanczos（白字抠色→alphaextract 反转成白底黑字）只取台词。
  两遍的结果分别由 `extractShot` / `extractDialogue` 处理，再合成一条记录。
- **缓存图一律临时 + 用完即删**（`_full.png` / `_crop.png` 与导出源图都删），不提供「保留抓帧」选项。
- **镜号来自画面 OCR 标签**（你重排过的号）。
- **行序 = 捕获顺序**；预览/导出都按镜号数值重排一次，同镜号保持捕获顺序。
  → 手动文件名编码「镜号 + 子序」的做法在面板里退休；调序/改镜号在表格内直接完成。
